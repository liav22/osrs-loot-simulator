## How a tier is decided

Highest applicable tier wins, checked in this order:

1. **E** — zero `dropsline` rows, every row is `Always`, or no denominator group reaches 3 rows. There is no main weighted table on the page; the real loot table lives on a reward-chest or raid page.
2. **D** — the bucket errored, a rarity is neither a fraction nor `Always`, or the main table overflows its denominator and a membership split does not fix it.
3. **C** — otherwise fine, but at least one row is flagged `rare_drop_table`.
4. **B** — carries `(m)` / `(f)` markers, or only the membership split fits.
5. **A** — the main table fits its denominator, no markers, no shared tables.

Two rules do most of the work here, and both matter:

- **The main table is the denominator group with the most rows**, and it must carry at least 3 rows to count as one. Smaller groups are pre-roll or tertiary drops, which never sum to their denominators and are not judged as if they should.
- **Summing *under* the denominator is not a defect.** Section 4.3 makes the remainder of a weighted table an implicit `nothing`, so a shortfall is expected. Only *overflowing* the denominator is evidence of a problem — that is the Brutus case, where members and free-to-play rows are interleaved into one rendered table.
